- Register integration routes: `app.register(registerIntegrationRoutes, { prisma, authService, systemKey: systemKeyBuf })` where `systemKeyBuf` is the resolved key
- In `start()` function (the `async` one that calls `app.listen`): before `app.listen()`, call `const systemKey = await ensureSystemKey(prisma, env.SESSION_SECRET)` and store it on the app instance or pass it through a Fastify decorator

IMPORTANT: The research recommends keeping `buildServer()` synchronous and adding a `systemKey` injection option. For tests, pass `Buffer.alloc(32)` as a fixed test key. For production `start()`, call `ensureSystemKey` async before listen and use Fastify's `addHook('onReady')` or a decorator to make the key available to routes. The cleanest approach per the research Option 3: accept `systemKey?: Buffer` in `BuildServerOptions`, and in `start()` do:
```typescript
const systemKey = await ensureSystemKey(prisma, env.SESSION_SECRET);

```

Alternatively, the simplest approach that avoids touching all test files: keep `buildServer` sync, add `systemKey?: Buffer` to options, pass it to integration routes. In `start()`, call `ensureSystemKey` and pass the result. Test files use `buildServer({ systemKey: Buffer.alloc(32) })`.

**3. Integration routes (per D-10, D-11, D-12, D-13):**

Create `apps/api/src/routes/integrations.ts` following the `bootstrap.ts` registration pattern:

```typescript
export type IntegrationRoutesDependencies = {
  prisma: Pick<PrismaClient, "integrationCredential">;
  authService: Pick<AgentSmithAuthService, "getSession">;
  systemKey: Buffer;
};
```

Implement three route handlers:

**GET /api/integrations/:key** (per D-10):
- Validate `:key` is `"intune"` or `"openai"`, return 404 otherwise
- Session guard via `requireAuth` preHandler (same pattern as bootstrap.ts)
- If no row found: return `{ configured: false, lastTestedAt: null, lastTestResult: null }`
- If row exists: decrypt with `decryptCredential(options.systemKey, row.encryptedValue, row.iv, row.authTag)`, parse JSON
- For intune: return `{ configured: Boolean(cred.clientSecret), tenantId: cred.tenantId ?? "", clientId: cred.clientId ?? "", lastTestedAt: row.lastTestedAt?.toISOString() ?? null, lastTestResult: row.lastTestResult ?? null }`
- For openai: return `{ configured: Boolean(cred.apiKey), lastTestedAt: row.lastTestedAt?.toISOString() ?? null, lastTestResult: row.lastTestResult ?? null }`
- NEVER return `clientSecret` or `apiKey` in any response

**PUT /api/integrations/:key** (per D-11):
- Session guard
- Accept JSON body with partial credential fields
- If existing row: decrypt existing, merge (blank/empty secret fields = keep existing per D-01), re-encrypt with fresh `encryptCredential` call (fresh IV)
- Upsert with `prisma.integrationCredential.upsert({ where: { key }, ... })`
- The `update` clause must only set `encryptedValue`, `iv`, `authTag`, `updatedAt` -- must NOT touch `lastTestedAt` or `lastTestResult` (Pitfall 4 from research)
- Return `{ ok: true }`

**POST /api/integrations/:key/test** (per D-12):
- Session guard
- Read stored credential row, decrypt
- For intune: call `testIntuneConnection(tenantId, clientId, clientSecret)` -- import `ClientSecretCredential` from `@azure/identity`, attempt `getToken("https://graph.microsoft.com/.default")` with 10s `Promise.race` timeout, map errors to human-readable messages
- For openai: call `testOpenAIConnection(apiKey)` -- create `new OpenAI({ apiKey, timeout: 10_000 })`, call `client.models.list()`, map errors
- Persist result: `await prisma.integrationCredential.update({ where: { key }, data: { lastTestedAt: new Date(), lastTestResult: result.ok ? "pass" : result.message } })`
- Return `{ ok: boolean, message: string }`

Error mapping for test-connection:
- Intune timeout: "Connection timed out after 10s"
- Intune AADSTS7000215 or "invalid client secret": "Auth failed: invalid client secret"
- Intune AADSTS90002 or "tenant": "Auth failed: tenant ID not found"
- Intune generic: "Auth failed: {message}"
- OpenAI 401 or "Incorrect API key": "Invalid API key"
- OpenAI 429: key IS valid, return `{ ok: true, message: "Rate limit reached -- key is valid" }`
- OpenAI generic: "Connection failed: {message}"
